User Manual

This guide explains how to authenticate, what each role can do, and how to call every Admin and Dashboard API endpoint.

Admin API

Protected with JWT. Manage users, roles, projects, deliverables, and overview stats.

Dashboard API

Public read-only project listing and detail for dashboard consumers.

1. Introduction

The API uses JSON over HTTP. Most admin endpoints require a Bearer token obtained from sign-in. Updates use POST on resource paths (not PUT/PATCH).

2. Base URL

http://<host>:<port>/api

Example: http://localhost:3030/api

3. Authentication

  1. Call POST /admin/v1/auth/sign-in with email and password.
  2. Receive a JWT token.
  3. Send it on protected requests:
Authorization: Bearer <token>
Content-Type: application/json
Tokens are valid for 30 days. Sign in again if you receive 401 Unauthorized.

4. Permissions

Access depends on the signed-in user’s role permission.

Action FULL_CONTROL PROJECT_MANAGEMENT
Sign in / view profile / update own profile Yes Yes
View overview, users, roles, projects, deliverables Yes Yes
Create / update / delete users Yes No (403)
Create / update / delete roles Yes No (403)
Create projects Yes No (403)
Update projects & deliverables Any project Only owned projects
Project owners must be ACTIVE users whose role permission is PROJECT_MANAGEMENT.

5.4 Permission decision flow

FULL_CONTROL

  • Manage users & roles
  • Create any project
  • Edit any project / deliverable
  • View overview and lists

PROJECT_MANAGEMENT

  • Cannot manage users or roles
  • Cannot create projects
  • Can edit only owned projects
  • Can manage deliverables on owned projects
Request
  └─ Authenticated?
       ├─ No  → 401 Unauthorized
       └─ Yes → Has FULL_CONTROL?
            ├─ Yes → Allow action
            └─ No  → Is action user/role/project-create?
                 ├─ Yes → 403 Forbidden
                 └─ No  → Editing project/deliverable?
                      ├─ Yes → Is project owner? → Allow / 403
                      └─ No  → Allow read / profile

6. Conventions

  • Pagination: add page and perPage query params.
  • Filters: pass matching field names as query params (e.g. ?status=OPEN).
  • Project codes: auto-generated as PMO0001, PMO0002, …
  • TAC date format: DD-MM-YYYY (example: 15-08-2026).
  • Password rule: min 8 chars, with uppercase, lowercase, number, and special character.

8. Profile

GET JWT /admin/v1/me

Returns the signed-in user’s profile (no password).

POST JWT /admin/v1/me 
{
  "name": "Jane Doe",
  "email": "jane@example.com",
  "employeeId": "EMP001",
  "password": "NewPass1!",
  "passwordConfirm": "NewPass1!"
}

All fields optional. Role and status cannot be changed here.

10. Users

JWT · Create/update/delete require FULL_CONTROL.

List users

GET /admin/v1/users

Filters: name, email, employeeId, status, roleId, plus page, perPage.

Get user

GET /admin/v1/users/:id

Create user

POST /admin/v1/users 
{
  "name": "John Smith",
  "employeeId": "EMP010",
  "email": "john@example.com",
  "roleId": 3,
  "status": "ACTIVE",
  "password": "Secure1!",
  "passwordConfirm": "Secure1!"
}

Update user

POST /admin/v1/users/:id

All fields optional.

Delete user

DELETE /admin/v1/users/:id

11. Roles

JWT · Create/update/delete require FULL_CONTROL.

12. Projects

JWT

List projects

GET /admin/v1/projects

Filters: code, name, department, status, stage, ownerId, and more project text fields.

Get project

GET /admin/v1/projects/:id

Includes projectOwners and deliveriables. TAC dates are returned as DD-MM-YYYY.

Create project

POST /admin/v1/projects

Requires FULL_CONTROL. ownerIds is required (one or more).

{
  "name": "Core Banking Upgrade",
  "department": "IT",
  "status": "OPEN",
  "stage": "INITIATION",
  "ownerIds": [3, 5]
}

code is generated automatically (e.g. PMO0007).

Update project

POST /admin/v1/projects/:id
  • FULL_CONTROL: can update any project
  • PROJECT_MANAGEMENT: only if user is an owner
  • To set COMPLETED, all deliverables must be COMPLETED and total percentage must be 100%

13. Deliverables

JWT · Create/update/delete allowed for full-control users, or owners of the related project.

List deliverables

GET /admin/v1/deliveriables

Filters: deliverable, tac (DD-MM-YYYY), projectId, projectCode, status.

Create deliverable

POST /admin/v1/deliveriables 
{
  "deliverable": "UAT sign-off",
  "tac": "15-08-2026",
  "completedPercentage": 0,
  "projectId": 1,
  "status": "OPEN"
}

Project totalPercentage is recalculated as the average of deliverable percentages.

Other actions

MethodPath
GET/admin/v1/deliveriables/:id
POST/admin/v1/deliveriables/:id
DELETE/admin/v1/deliveriables/:id

17. Quick Start

# 1) Sign in
curl -X POST http://localhost:3030/api/admin/v1/auth/sign-in \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@example.com","password":"YourPassword1!"}'

# 2) Get overview
curl http://localhost:3030/api/admin/v1/overview \
  -H "Authorization: Bearer <token>"

# 3) Create a project (FULL_CONTROL only)
curl -X POST http://localhost:3030/api/admin/v1/projects \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"name":"New Initiative","ownerIds":[3]}'

# 4) Add a deliverable
curl -X POST http://localhost:3030/api/admin/v1/deliveriables \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"deliverable":"Kickoff","tac":"30-07-2026","projectId":1}'
